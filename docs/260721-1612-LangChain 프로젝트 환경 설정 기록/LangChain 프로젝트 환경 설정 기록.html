2. 설치 항목별 이유와 필요

이번 설정은 프로그램을 많이 설치하는 것이 목적이 아니라, AI Agent가 프로젝트 노트북을 재현 가능하게 실행하고 Ollama를 주력으로 사용하면서 Groq을 비교할 수 있는 최소 실행 기반을 만드는 것이 목적입니다.

설치 또는 설정어떻게 준비했는가왜 필요한가
Python 3.12.12 uv python install 3.12로 설치했습니다. 프로젝트 프로젝트가 Python 3.10 이상 3.13 미만을 요구합니다. 시스템 Python 3.14.6은 조건을 벗어나므로 사용하지 않았습니다.
uv 0.11.29 이미 설치되어 있던 Homebrew의 uv를 사용했습니다. Python 버전, 가상환경, 패키지 설치를 한 흐름으로 관리하고 uv.lock에 고정된 의존성을 재현하기 위해 필요합니다.
.venv 가상환경 uv venv --python 3.12 .venv로 프로젝트 폴더 안에 생성했습니다. 이 프로젝트의 LangChain과 Jupyter 패키지가 다른 프로젝트의 Python 패키지와 충돌하지 않게 분리하기 위해 필요합니다.
프로젝트 의존성 161개 uv sync --python .venv/bin/python으로 pyproject.toml과 uv.lock 기준 설치했습니다. 노트북 전체에서 필요한 LangChain, LangGraph, provider 통합, RAG, PDF 처리 기능을 한 번에 사용할 수 있게 하기 위해 필요합니다.
Jupyter와 ipykernel 의존성에 포함된 Jupyter를 설치하고 langchain-agent-v1 커널을 등록했습니다. 사용자가 Jupyter Lab을 직접 조작하지 않더라도 AI Agent가 .ipynb 셀을 순서대로 실행하고 결과를 저장하려면 노트북 실행 커널이 필요합니다.
LangChain 핵심 패키지 langchain 1.2.15, langchain-core 1.3.2, langchain-community 0.4.1 등을 설치했습니다. 02번 이후의 LCEL, 프롬프트, 구조화 출력, Tools, Agents, RAG 예제를 실행하는 기본 프레임워크입니다.
Ollama 앱과 통합 Homebrew Cask로 Ollama 0.32.1을 설치하고 앱을 실행했습니다. Python 쪽에는 langchain-ollama 1.1.0이 설치되었습니다. 외부 API 키 없이 Mac에서 모델을 직접 실행하여 Ollama를 이번 학습의 주력 LLM으로 사용하기 위해 필요합니다.
Ollama bge-m3 ollama pull bge-m3로 설치했습니다. 실제 임베딩 벡터 차원은 1024였습니다. 03번 예시 선택자와 06번 RAG가 문장의 의미를 벡터로 바꾸는 임베딩을 필요로 합니다. 생성 LLM과 별개로 RAG 기반 실습에 필요합니다.
Ollama gemma4:e2b ollama pull gemma4:e2b로 설치했습니다. 실제 모델 목록에서는 7.2GB로 표시되었습니다. 질문에 답하고 체인을 실행하는 로컬 생성 LLM이 필요하기 때문입니다. 컴퓨터 메모리 48GB에서 주력 모델로 실행할 수 있고, 더 큰 모델 다운로드가 실패했을 때 선택한 현실적인 경로입니다.
Groq 통합 langchain-groq 1.1.2와 Groq Python 패키지를 설치했습니다. API 키는 아직 입력하지 않았습니다. Ollama로 먼저 실행한 같은 입력을 클라우드 모델로 다시 실행하여 응답 품질과 속도를 비교하기 위해 필요합니다. 실제 호출에는 사용자의 Groq API 키가 추가로 필요합니다.
.env 환경 변수 .env.example을 .env로 복사했으며 API 키 값은 비워 두었습니다. Groq, Tavily 같은 외부 서비스의 비밀값을 코드와 분리하기 위해 필요합니다. 키가 없으면 Ollama 실습은 가능하지만 Groq과 Tools 웹 검색은 실행할 수 없습니다.
설정의 핵심
Jupyter는 사용자가 직접 코딩하기 위한 도구가 아니라 AI Agent가 노트북을 실행하기 위한 실행면으로 유지했습니다. Ollama는 로컬 생성과 임베딩의 기본 경로로 두고, Groq은 같은 입력을 비교하는 보조 경로로 남겨 두었습니다.

3. 어떤 순서로 설정했는가

  1. 기존 작업공간을 확인하고, 프로젝트 코드가 없음을 확인했습니다.
  2. 기존 프로젝트를 덮어쓰지 않도록 프로젝트 저장소를 langchain-agent-v1/에 clone했습니다.
  3. 프로젝트가 요구하는 Python 범위가 >=3.10,<3.13이므로, 시스템의 Python 3.14.6은 사용하지 않았습니다.
  4. uv로 Python 3.12.12를 설치하고 .venv를 생성했습니다.
  5. uv sync로 프로젝트 의존성 161개를 설치했습니다.
  6. Jupyter 커널 langchain-agent-v1을 등록했습니다.
  7. Homebrew Cask로 Ollama 앱을 설치하고 실행했습니다.
  8. Ollama에 bge-m3와 gemma4:e2b를 다운로드했습니다.
  9. LangChain을 통해 생성 모델과 임베딩 모델을 각각 실제 호출했습니다.
모델 선택 기록
처음에는 gemma4:e2b를 시도했지만 실제 다운로드 크기가 약 9.6GB였고 다운로드 중 네트워크의 unexpected EOF가 발생했습니다. 같은 대용량 다운로드를 반복하지 않고, 현재 프로젝트 설정에 함께 안내된 gemma4:e2b로 전환했습니다. 실제 모델 목록에서는 약 7.2GB로 표시됩니다.

4. 설치와 실행에 사용한 핵심 명령

git clone https://github.com/richlegendai/langchain-agent-v1.git langchain-agent-v1
cd langchain-agent-v1
uv python install 3.12
uv venv --python 3.12 .venv
uv sync --python .venv/bin/python
uv run python -m ipykernel install --user --name=langchain-agent-v1 --display-name='LangChain Basic (Python 3.12)'
brew install --cask ollama
open -a Ollama
ollama pull bge-m3
ollama pull gemma4:e2b

나중에 AI Agent가 이어서 실행할 때는 프로젝트 저장소에서 uv run을 사용하면 별도 activate 없이 같은 가상환경을 사용할 수 있습니다.

5. 실제 검증 결과

  • Python 3.12.12로 가상환경 실행
  • Jupyter, ipykernel, LangChain, langchain-ollama, langchain-groq import 성공
  • Ollama 생성 모델 gemma4:e2b 호출 성공
  • Ollama 임베딩 모델 bge-m3 호출 성공
  • 임베딩 벡터 차원 1024 확인
  • 두 모델 모두 Ollama에서 100% GPU로 로딩 확인
  • Groq 실제 API 호출은 API 키가 없어 아직 실행하지 않음

6. 아직 하지 않은 작업

  • Groq API 키를 입력하지 않았습니다. 사용자가 직접 키를 준비한 뒤 설정합니다.
  • 프로젝트 01번부터 06번까지 전체 노트북 실행은 아직 시작하지 않았습니다.
  • 01번 노트북은 OpenAI SDK 인터페이스로 Ollama gemma4:e2b를 호출하도록 수정했으며, 실제 셀 실행 확인이 필요합니다.
  • 04번 Tools 예제의 Tavily API 키는 설정하지 않았습니다.
